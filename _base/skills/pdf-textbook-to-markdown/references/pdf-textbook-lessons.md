# PDF Textbook Lessons

Accumulated reusable lessons from real conversions. Add new entries at the end of the matching section; keep each lesson compact and source-agnostic.

## Post-extraction polish is a mandatory second pass

The raw output of `extract_pdf_textbook.py extract` is a debugging artifact, not a readable book: it carries `## Page N` breaks every page, per-page footer numbers, running headers repeated hundreds of times, broken hyphenation, mojibake, and each PDF text cell as its own line. Do not hand the raw file to the user as a "converted book" — always run `scripts/polish_pdf_extraction.py <file.md> [<file.pdf>]` afterwards. Passing the PDF path lets the polisher insert `## Chapter …` headings from the outline; without it the polisher falls back to detecting `^\s*ГЛАВА\s+\d+` in the body text. Polish is idempotent — safe to re-run.

## PyMuPDF text extraction artifacts (what the polisher fixes)

- **Mojibake `×èñëî áðàêîâ` = `Число браков`.** Cyrillic bytes in a CP1251 font glyph table decoded as Latin-1. Detected as tokens made entirely of `[\x80-\xff]` accented chars; round-tripped via `encode('latin-1').decode('cp1251')`. Only triggers on tokens with ≥2 such chars, so ASCII prose is untouched. On one 850-page devotional book: 4296 tokens fixed automatically.
- **Private-Use-Area glyphs `U+E000..U+F8FF`.** Custom-font glyphs Obsidian renders as replacement squares (□). Often decorative bullets/dingbats; occasionally lost letters. Polisher marks each as `⟨PUA U+XXXX⟩` so a human can scan and decide — do not silently strip.
- **Broken tables — each cell on its own line.** PyMuPDF reads text by layout coordinates; a numeric table with 20 columns × 10 rows produces 200 short lines in reading order. Detect as runs of ≥12 consecutive non-empty non-block lines ≤20 chars each; replace with an HTML-comment marker `<!-- TABLE #NNN — reconstruct from PDF p.N -->` and save original cell text to `<stem>.table-NNN.txt` sidecar. Do not try to auto-reconstruct — column boundaries are ambiguous from text alone; sidecar + PDF is a good tool for a human.
- **Running headers/footers.** Chapter title + book title + page number appear at the top/bottom of every page. Detect as lines appearing verbatim in ≥5 pages (uniquely per page); strip. But — this pass can eat legitimate chapter-start titles if the title itself is the running header (see next lesson).
- **Page markers `## Page N` and `<!-- source-page: N -->`.** Useful for locating tables and inserting chapter headings; strip after those passes are done. Never present them as content.
- **Hyphenation.** Words split across line boundaries as `слово-\nостаток`. Unwrap only when the tail starts with a lowercase letter; otherwise keep the dash (may be a real dash or a dialogue marker).

## Chapter splitting: order-of-operations matters

- **Insert chapter headings BEFORE stripping running headers**, when the PDF has an outline: outline entries index into `<!-- source-page: N -->` markers; insertion at each marker produces `## <Title>` at the right position. Sort outline entries by page ASCENDING and iterate in REVERSE order so later-page inserts don't shift earlier positions; for same-page groups, reverse the outline-index too so first-outline entry ends up first in text.
- **Fallback text-based detection runs AFTER running-header stripping**, when the PDF has no outline (Немцев/Winkler-style books): pattern `^\s*ГЛАВА\s+\d+.*` on line start. Running-header stripping usually removes the per-page repeats; the surviving occurrence is the true chapter start. But if the chapter title *is* the running header (repeats verbatim on every page), the stripper removes even the actual first occurrence, leaving only a shorter `ГЛАВА N` label somewhere else, and the auto-inserted heading loses its title. **Rename the chapter files manually from the book's own TOC in this case** — it takes 30 seconds and there is no cleaner automatic fix that doesn't risk missing real chapter starts.
- Split by `^## ` headings into per-chapter files via `scripts/split_by_chapters.py`. The big .md becomes an index with wiki-links to chapter files; original chapter body opens each file as `# <Title>`.

## Do not present a raw or half-polished extract as "converted"

Users see the raw extraction as a broken deliverable, not as "a first pass we'll clean later" — even if the docstring says so. Run polish + split + (if applicable) `spiritual-literature/scripts/resolve_bible_refs.py` in one pipeline; deliver the chapter folder and the index. If the user later wants raw page anchors, they're in the .cleanup.json report.



## Word "Print To PDF" documents (theses, reports)

- Broken Word `REF` fields print as the literal artifact «Ошибка! Источник ссылки не найден.» throughout the PDF. Every in-text bibliography number is then unrecoverable from the PDF itself — recover citation numbers from the source `.doc`/`.docx` when available, and if not, state explicitly in the conversion note that reference numbers are lost; never invent them.
- PDF metadata `title` of such documents is often mojibake (cp1251/UTF mix from the Word filename). Harmless; do not treat it as an OCR-quality signal.
- Formula-heavy pages keep a full text layer, but equations extract as per-glyph vertical scatter (symbols split line by line). Do not transcribe formulas from the extracted text — use rendered page images as ground truth.

## Markdown-native open textbooks (GitHub, MkDocs)

- A GitHub/MkDocs textbook needs no extraction: clone it, verify the licence first (Apache-2.0/CC → translation and vault copy are permitted; keep LICENSE and attribution), then work directly on the chapter `.md` files. Check math delimiters — MkDocs sources often already use `$...$`/`$$...$$`, which Obsidian accepts as-is.
- For full translation, fan out one subagent per ≤~10k source words (split large chapters by file ranges; two agents may write into the same destination folder — different numeric prefixes never collide). Put the common rules (terminology policy, embed rewriting, footer line, file-naming rule) into ONE shared rules file and give each agent a two-line assignment pointing at it — prompts stay tiny and the rules stay consistent.
- Copy the book's shared `images/` once into `attachments/` with a unique per-book prefix (e.g. `mcsai-<name>.svg`), and have agents rewrite `![alt](../images/X.svg)` → `![[<prefix>-X.svg]]`. Verify afterwards by counting: total embeds in translation must equal total image links in source, and per-chapter counts must match; also check every embed filename exists.
- Agents killed by session limits or dropped connections usually leave whole files either complete (tail contains the footer/source line) or absent — the per-file footer line doubles as a completeness marker. Resume the same agent with a message («допиши файл X») instead of relaunching: its context (rules + source already read) survives, so the retry costs little.
- Expect ~13–14 output-tokens per source word end-to-end for EN→RU translation agents (rules reading included) — use this to size the fan-out before launching.

## Large documents (200+ pages)

- Render all pages to PNG early (`page.get_pixmap(dpi=170)`): the images serve simultaneously as formula-transcription ground truth, figure-crop source, and OCR fallback, and cost little time or disk.
- For chapter-level summarization or cleanup, fan out parallel subagents: give each agent the extracted-Markdown line range for its chapter, computed by grepping the `## Page N` anchors emitted by `extract_pdf_textbook.py`. Instruct agents to mark unreadable formulas as «[формула нечитаема]» rather than guessing; require per-chapter term lists with page anchors so the synthesizer can build term notes without re-reading the source.
- When the same work exists as PDF + source `.doc`/`.docx`, treat the pair as one source: prose and structure convert best from the DOCX route (`docx-to-markdown` skill), while the PDF supplies page anchors and rendered ground truth for formulas and figures.
- The PDF-only full-conversion route is proven viable when the DOC route fails (e.g. Word COM `SaveAs2` never completes): prose from the PDF text layer, every formula transcribed to LaTeX against the page render, figures cropped from the PDF with an iterative crop-verify loop (render `page.get_pixmap(clip=...)` → visually inspect the crop → adjust bbox; expect 1–2 re-crops per tricky multi-panel figure). A 214-page, ~450-formula dissertation converted this way with only one formula left as an image.
- Replace the broken-REF artifact «Ошибка! Источник ссылки не найден.» with one compact inline marker (e.g. `[лит.?]`), collapsing runs of consecutive artifacts into a single marker, and explain the convention once in the book/index note — not in every chapter note.
- Vault note validators aimed at authored term notes (e.g. a Strict rule "display formula must be followed by a `Где:` block") do not apply to full-text conversion notes, where the source's own prose explains notation. Validate conversions with the non-strict profile: UTF-8, headings, link balance/resolution, embed existence.

## pdf-inspector batch conversions (datasheets, specs, forum/web PDFs)

Verified 2026-08-06 on a 185-PDF vault batch plus a 32-note scientific-refactoring pass over the output.

- **pdf-inspector artifact patterns to sweep for.** (a) *Letter-spaced figure dumps*: vector diagrams embedded in text pages extract as spaced-out glyph runs («D A T _ I / D A T _ O … B Y T E»); detect with a regex for ≥6 single chars separated by single spaces, replace each dump with an italic caption stub `*Figure N-M: description (текстовый дамп схемы удалён)*` cross-checked against the source PDF. (b) *Stitched two-column tables*: PDF table cells from two independent columns interleave into one garbled Markdown table — re-split against the source PDF (Read handles PDFs page-by-page) or mark the block as converter-damaged; never leave it silently. (c) Datasheet strap/pin tables merge auxiliary rows into signal rows with cell shift — same fix.
- **Remove running headers line-anchored, never with `\s*`-greedy regexes.** A regex spanning line boundaries glues the paragraphs on both sides of every removed page break; the damage is invisible afterwards (reads as one paragraph) and a Google-Drive vault has no git history to restore from. Process line-by-line and delete whole lines only.
- **Two-layer pattern for reference documents.** Do not rewrite a datasheet/spec body: prepend a project-oriented «#### Выжимка» (with a «Ключевое для проекта» block and wiki-links into the vault), clean artifacts, add term links at key places, and keep the reference body. Full задача→метод→вывод restructuring is for articles/forum threads/papers only.
- **Parallel refactoring agents must not create term notes.** Fan-out agents propose terms (exact proposed title used in their `[[links]]`, 1-2 sentence definition, needing notes); a single dedupe agent then merges synonyms, checks the vault case-explicitly (Cyrillic does not case-fold in grep), and only after that are the term notes created and links reconciled. This eliminated duplicate-term collisions across 9 parallel agents (40 proposals → 38 unique notes, 2 renames).
- **Revision/duplicate PDFs convert into duplicate notes.** Multiple revisions of one spec (Wishbone B3/B4, Gowin DS102 ×3) and stray copies («X 1.pdf», same file in two folders): make the newest revision the canonical note, reduce the others to a one-line pointer «Дубликат/ревизия — см. [[canonical]]»; never delete the PDFs.
- **Adversarial critic pass pays for itself.** A final agent that greps for residual artifact patterns and spot-checks 6-8 notes against the source PDFs caught inconsistent figure-dump cleanup and stitched tables that per-note validation (link/style checks) structurally cannot see. **But pin the critic to re-read each file immediately before judging** — one critic reported ~100 residual figure dumps in a file another agent had already cleaned minutes earlier, and the follow-up agent proved the claim false with three independent detectors. A stale-read critic costs a whole wasted repair cycle.

## Reconstructing damaged blocks (second-wave lessons, 2026-08-06)

From a 130-note refactoring sweep over pdf-inspector output. These are about *recovering* content the converter mangled, not about detecting it.

- **`Read` may not open PDFs at all — check before concluding a block is unrecoverable.** In a Windows/Git-Bash environment without poppler, the Read tool fails on PDFs, and agents silently conclude "no source access" and stamp blocks as permanently damaged. PyMuPDF (`fitz`) was installed the whole time. Write one `pdfdump.py` helper (`page.get_text("blocks")` sorted by column) into the shared scratchpad and reference it from the rules file — every agent then reconstructs instead of surrendering.
- **Revisit every "damaged by converter" mark once a working PDF route exists.** In the first audited file, 3 of 4 marks were removable — the values were readable, merely un-extracted. A whole-appendix set of Verilog listings previously declared unrecoverable was restored in full (33 KB → 85 KB note) once line numbers were separated by `x < 50` and running headers by `y`. Budget an explicit revision pass; do not treat the marks as final.
- **Use word coordinates, not judgement, to assign values to columns.** `page.get_text("words")` returns x/y per token. A landing-pattern table whose MIN/NOM/MAX headers sit at x≈323/364/408 assigns its values by matching x within a pixel. Rotated table headers and ✓/✗ matrices reconstruct the same way. State in the note that the column was inferred from coordinates — the reader deserves to know which facts are transcribed and which are derived.
- **Monospace listings need the clip widened.** Text that overruns the page text-box gets truncated by a default `get_text` call; indentation and ASCII art in comments must be rebuilt from the x of the first glyph (measure the monospace pitch once, e.g. 5.23 pt, and divide).
- **Agents paraphrase code when transcription is hard — check for it.** Two "restored" listings turned out to be reformatted (ports rearranged, comments invented) rather than transcribed. A verbatim-only instruction plus a review pass caught it. Same failure mode as inventing table values, but harder to spot because paraphrased code still looks plausible.
- **Never let a validator warning justify editing the author's text.** Agents repeatedly inserted a space into source code (`arr[i] ];`) to silence a bracket-balance warning. Forbid it explicitly in the rules file; verify the false positive by counting `[[`/`]]` outside fenced blocks instead. Also correct a tempting-but-wrong fix: wrapping the fragment in a fenced block does **not** silence `Test-Note.ps1` (it counts brackets over the whole text; fences are skipped only for heading and mermaid checks) — it is still worth doing for rendering, but expect the warning to remain and run without `-Strict` on those files.
- **Code constructs that look like wikilinks are a real vault hazard, not cosmetics.** C++ attributes (`[[noreturn]]`, `[[fallthrough]]`, `[[carries_dependency]]`) and POSIX classes (`[[:alpha:]]`, `[[:digit:]]`) render as live Obsidian links; clicking one creates an empty stub note in the vault root. After converting any C/C++/regex-heavy book, sweep for them **outside** fenced and inline code and wrap them in backticks.
- **Close the loop with a completeness audit script — fan-out planning silently drops files.** Across a 170-note sweep dispatched as ~15 agent groups, 8 notes were never refactored: 2 books were left out of every group by mistake, 5 became canonical during deduplication after the dedupe agent was told "canonical notes will be refactored by another pass" that was never scheduled, and 1 collection was simply missed. No agent reported a problem — each did exactly its assignment. Write a script that flags any note still carrying the untouched conversion signature (exact original first line AND no summary/structure marker), and run it before declaring the job done. Pair it with mechanical checks the per-note validator cannot do vault-wide: heading levels, blank line after heading, wikilink resolution against a full vault index, pseudo-wikilinks outside code, residual letter-spaced dumps, bracket balance computed *outside* fences. Two detector iterations were needed — the naive "raw source line present" test flagged 57 files, most of which were correctly refactored two-layer references that legitimately kept that line.
- **Deduplication can break references in the surviving note.** After copies were reduced to pointers, the canonical note still told readers that the hex dumps "are in the copy" — content that no longer existed there. When collapsing duplicates, grep the canonical note for mentions of the copy and repoint them at the source PDF.
- **Verify a document's identity against its content, not its filename.** Two files in one sweep contained different books than their names claimed (a "5th edition of X" that was actually Wakerly's *Digital Design*; a "…in C" that was Goodrich's *…in C++*). Cheap check: grep the body for author surname, ISBN, and running-header signatures. Record the finding in the note; leave renaming to the vault owner, and check whether existing notes cite the file under the wrong attribution. When the owner does authorise the rename, rename the `.pdf` and its `.md` together, rewrite every inbound wikilink in the same pass, and keep a short "history of this filename" section in the note — the old name may still appear in the owner's external records or sync history.

## Surviving a session-limit kill in a fan-out (2026-08-06)

A fan-out of 8 parallel agents was killed mid-run by a session quota: 1.77M tokens spent, the orchestrating script returned zeros. Understanding exactly what is lost is what makes the loss cheap next time.

- **Disk writes survive; everything else burns.** File edits are applied immediately, so completed notes stay complete — 8 notes written minutes before the kill were intact and needed no redoing. What evaporates is the agent's context (everything it read and reasoned about), its final report, and every downstream stage of the pipeline (dedup, term-note creation, link reconciliation, critic never ran). Tokens are consumed at read/think time and are not refunded.
- **An agent killed during its reading phase loses 100%.** It paid for the whole context and produced nothing. This is the single strongest argument for the shared-rules-file pattern: it shortens the phase that is most expensive to lose. Ordering the work so that each agent writes something early (first file, then the rest) converts a total loss into a partial one.
- **Require a progress journal on disk, not only a final report.** Without one there is no record of what got done: reconstructing the state meant digging through file modification times. Have each agent append one line per finished file to a shared log.
- **Do not conclude "nothing was written" from a narrow time window.** Checking only files modified in the last 90 minutes showed zero and produced a confidently wrong conclusion; the writes had happened outside that window. Enumerate by full timeline (sort every candidate file by mtime since the run started) before declaring the state clean, and correct the record openly if an earlier claim was wrong.
- **Prefer many small agent calls over few large ones.** Workflow resume replays *completed* calls from cache; in this run zero completed, so nothing could be replayed. Finer granularity means more of the work is already cached when you resume.
- **Individual agents degrade more gracefully than a workflow.** In a workflow the agents die together and the script's post-processing never runs. Independently spawned agents die one at a time, and a finished one can be continued with a message — its context survives, so a follow-up task costs a fraction of a fresh agent. Two follow-ups in this sweep (finishing leftovers, extending a recovery pass) reused context this way.
- **Launch in waves sized to an unknown quota.** Eight simultaneous agents against an invisible limit lost everything at once; waves of three or four would have lost only the current wave.

## Rebuilding flattened tables in an already-converted book (2026-08-24)

From repairing all 113 tables of a 854-page FrameMaker manual (ModelSim 10.5b) whose first conversion had dumped every table cell onto its own line. The repair is scriptable, but three of its failure modes silently corrupt text, so the guards matter more than the extraction.

- **`find_tables().extract()` loses underscores; `page.get_text()` keeps them.** This PDF family draws `_` as a separate glyph on its own line, so cells come back as `sv lib` plus a stray `'_'` where the source says `sv_lib`. Drop the stray `_`-only fragments and take each fragment's spelling from the *converted note*, which already reassembled them. A blanket "restore every underscored token seen in this chapter" fallback is tempting and wrong — it glued the legitimate phrase `bit vector` into `bit_vector`. Gate the fallback to cells that actually carry a stray `_` fragment AND whose text is absent from the note, then audit every underscored token in a rebuilt table against **its own page's** text — a chapter-wide audit passes the bad ones, because the correct token usually exists elsewhere in the chapter.
- **Match the note block as a text stream, not line by line.** The converter freely joined two cells onto one line and split others, so cell-by-cell comparison fails on ~60% of tables. Concatenate the PDF table's text into one whitespace/underscore-insensitive key and consume note lines while they remain a prefix of it. Add an order-free second tier (character multiset that must be *exactly* exhausted) for tables whose cell order the converter permuted; between the two, 60 of 113 tables converted unattended and none silently ate prose.
- **Buffer and re-emit interleaved content.** A table split across a page break routinely has a paragraph, a heading, or a footnote sitting between its halves. Buffer non-matching lines, resume if the stream continues, and re-emit the buffer after the assembled table; requiring the stream to complete exactly is what keeps this from swallowing real text.
- **A caption for a *different* table must terminate the block.** Skipping every `**Table …**` line to get past the repeated `(cont.)` caption deleted a neighbouring table's caption outright. Only skip a `(cont.)` caption whose table number matches the one being assembled.
- **Gate every bulk edit on a word-multiset diff, captions excluded.** Comparing `Counter(re.findall(r"[A-Za-z0-9_]+", text.lower()))` before and after caught all three corruption bugs above, and reduced the final audit to one deliberate deviation. Expect the merged tables' repeated header rows to show up as "lost" — list them and eyeball that they are only column headers. Do not test with substring containment: cell joins insert `|` and `\|`, producing false alarms that waste a diagnosis cycle.
- **Verify agents mechanically, then let them do the judgement.** Borderless tables (no ruling lines) defeat `find_tables()` entirely, and `strategy="text"` just returns the whole page as one table. Hand those to subagents with a coordinate-dumping helper (`get_text("words")`, cluster by y for rows and x for columns) plus the word-multiset checker they must run themselves — the script decides what is faithful, the agent decides the column layout. One agent also caught a bug the automatic pass had introduced in a table outside its own assignment.

## Two conversion defects that silently DELETE text in Obsidian

Both are invisible in the Markdown source and only show up in Reading view, so they survive every review that reads the `.md`. Sweep for them in any converted manual, datasheet, or CLI documentation.

- **`<placeholder>` is parsed as raw HTML and disappears.** `vsim -wlf <filename>` renders as `vsim -wlf `. CommonMark's tag name is `[A-Za-z][A-Za-z0-9-]*`, so `<filename>`, `<n>`, `<path>`, `<time>` vanish while `<install_dir>` and `<bootstrap_file>` survive (an underscore is not a legal tag name) — which is why the damage looks arbitrary and gets dismissed as noise. One 21-note book carried 354 of them. Fix by wrapping the whole whitespace-delimited word in backticks, so `<filename>.v` stays one token.
- **Two `$` on one line become inline math.** `$setup/$recovery` renders as italic `setup/` and eats the rest; `($$)` opens a display-math block. Only wrap where a span would really parse (`\$(?!\s)[^$\n]*?(?<!\s)\$`) — a lone `$display(...)` is harmless, and wrapping every `$token` mangles unfenced code samples. Never apply inside headings (backticks there break `[[#anchor]]` links) or inside `[[wikilinks]]`.

## Vault-wide sweep of every PDF (2026-08-27, 2211 files / 114 618 pages)

Converting the whole vault in one pass, rather than one book at a time, surfaces failure modes a single conversion never reaches.

- **Triage the whole corpus first — it costs a minute and it sizes the job.** One PyMuPDF pass over 2211 files (page count, sampled chars/page, md5) took 69 s and answered every planning question: how many are scans, how many are byte-identical copies, what the worst-case page count is. Do this before choosing routes, not after the first slow book.
- **`pdf_inspector.process_pdf` can hang for tens of minutes with no progress signal, and an in-process Rust call cannot be interrupted.** A 3357-page reference manual finished in 45 s; a 6049-page encyclopedia was still running after 18 minutes. Run the extractor in a child process with a page-scaled timeout (`min(420, max(150, pages*0.2))` worked) and fall back to plain PyMuPDF, saying so in the note header. Without the guard one book pins a worker slot for the rest of the sweep.
- **A "text_based" PDF can still be pure garbage: a broken ToUnicode CMap yields control codes, not letters.** 32 of 2211 files extracted at 70–78 % C0 control characters — identical output from pdf-inspector, PyMuPDF and pdftotext, because the defect is in the file. Detect mechanically (control-char share > 5 %) and write an OCR stub instead of the "text". The remedy needs `ocrmypdf --force-ocr`: without it OCR skips the file, seeing a text layer that is technically present.
- **Tie the running-header threshold to the page count, never to a fixed repeat count.** A flat "appears ≥5 times → delete" rule quietly eats a phrase a book legitimately repeats six times, and the loss is invisible in review. `max(6, pages*0.35)` keeps real headers (they appear on most pages) and spares real text. On the 6049-page encyclopedia this removed exactly 6044 header lines.
- **Escape source text that looks like a wikilink, do not backtick it.** `[[An]n]` (a double vector product) and a mangled citation `[1]]-[3]` render as live Obsidian links; clicking one creates an empty stub in the vault root. Rewriting the first bracket as `[\[` keeps the text visually identical and kills the link, whereas backticks change the author's typography. Leave a lone unmatched `]]` alone — with no opener it links to nothing, and editing it only serves the bracket-balance validator.
- **Convert once per unique content, and make the copies pointer notes.** 403 of 2211 PDFs were byte-identical duplicates across folders (the same course materials filed twice). Hashing first cut the extraction work and produced a vault where each copy says "совпадает с [[canonical]]" instead of a second full text that will drift.
- **Never overwrite a note the converter did not write.** Stamp generated notes with a marker comment (`<!-- vault-conversion:v1 -->`) and skip any existing `.md` without it. Then audit those skips: of 267 pre-existing notes, 259 were genuine, 6 were deliberate one-line pointers or image-only notes, and only 2 were empty stubs whose source really had never been converted — those got a `(полный текст)` sibling rather than an edit to the user's note.
- **Flush the progress journal after every record, not every N.** Buffered journal writes made a healthy 15-minute run look like it had produced nothing, which cost a wrong diagnosis and a killed run. The journal is the only crash-proof record of what finished.
- **Audit the vault, not the journal, and fix the audit's false positives before trusting it.** The first sweep reported 142 "raw LaTeX delimiters", 76 "unbalanced `[[`" and 2 "heading level < 4" — every one a checker bug: pandoc escapes a literal `[` as `\[`, a Wikipedia footnote `[\[1\]](url)` is not a wikilink, and `#` inside a fenced block is code. A checker that cries wolf hides the three real defects underneath it.

### Four text-layer defects that survive every route, and how to tell them apart

All four look like "the text extracted fine" until someone reads the note. Detect each mechanically; only the first is repairable.

- **CP1251 decoded as Latin-1** — «Ïåðåâîä» for «Перевод». *Repairable.* Convert runs of affected characters, not whitespace tokens: a token test misses single-letter Russian words (`â` for «в») and anything wearing a Markdown marker (`*Ïåðåâîä`), which is most of an emphasised line — on four Tolkien volumes the token version left more damage than it fixed. Gate on two document-level tests, because `ü ö ä ß é` are also Latin-1: affected letters must exceed ~2 % of all letters, **and** at least half of them must sit in runs of two or more. In real German the accented letters stand alone inside Latin words (M-ü-ller); in CP1251 debris they clump into whole words. Without the clustering test, "Müller ging über die Straße" is rewritten to "Мьller ging ьber die StraЯe".
- **Broken glyph table (ToUnicode)** — *not repairable, needs OCR.* Two shapes of the same defect: the text extracts as C0 control codes, or as letters from Latin Extended-A and the spacing-modifier block, so «Библия» comes out as «`ŁÆºŁ». Thresholds that separated cleanly on a 2211-file vault: control characters > 5 % of the text, or Latin-Extended/modifier letters > 10 % of all letters — the 12 damaged files scored 24–97 %, the next file scored 1.95 %. Do not waste time on codepage round-trips: twelve from/to combinations all failed, because the mapping is gone from the file, not mis-selected. The OCR command needs `--force-ocr`, or OCR skips the file on the strength of the bogus text layer.
- **Formulas set in the Symbol font** — *not repairable, but the note is still worth keeping.* The integral sign extracts as `ò`, infinity as `¥`, the pieces of a large bracket as `æ ö ç ÷ è ø`. Prose around them is perfect, so this is a warning in the note header, not a stub: 61 of 1907 notes in one vault. The mapping cannot be inverted without font information the extracted text no longer carries — `j` is φ inside a formula and an ordinary letter in the sentence beside it.
- **Body prose wrapped into a Markdown table** — *repairable, carefully.* On a two-column page the table detector can fire on running text, and whole paragraphs become table cells; no text is lost, but the note reads as a wall of grid. Unwrap only when at least ~60 % of a table's non-empty cells are long prose, and keep (with a marker comment) any table carrying a `Table N` / `Таблица N` caption — that one is a real table the converter mangled, and flattening it destroys the row meaning. **Do not reach for "a long cell means it is not a table"**: the STM32H7 reference manual's genuine register-description cells run to 2208 characters, and the conservative share rule left all 2609 of its tables untouched while still fixing 143 fake ones elsewhere.

Related: measure before switching routes. A single ugly two-column paper suggested pdf-inspector was mixing columns everywhere and that plain PyMuPDF should replace it for the ~670 two-column PDFs; measuring lost-space and table-density artefacts across 60 files showed no systematic difference, and the wholesale switch would have thrown away pdf-inspector's headings for nothing.
